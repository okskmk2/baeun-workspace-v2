결제 실패로 슬롯이 만료됐을 때의 패널티와, 워크스페이스를 다른 날에 샀을 때 일자를 깎지 않는 결제 주기 규칙을 기획으로만 정리합니다.

---

## 1. 한 줄 원칙

슬롯이 부족해져도 **이미 만든 조직·사람·일은 지우지 않는다.** 패널티는 **새로 자리를 여는 행위만 잠그고**, 스토어로 보내는 것이다.

결제 주기는 **계정 전체 갱신일로 맞추지 않는다.** 산 날부터 한 달씩, **구매 건( Polar 구독 )마다 독립**이다. 나중에 산 자리를 먼저 산 자리에 붙여 일괄 청구하면 남은 날짜를 잃는다.

시작 허용량은 과금하지 않는다. 워크스페이스 1, 워크스페이스당 프로젝트 3, 워크스페이스당 멤버 5(소유자 포함). 이 구간은 만료도 결제일도 없다.

---

## 2. 슬롯이 만료되면

만료 정의: 해당 유료 구독의 `end_date`가 지났거나, Polar에서 미납·해지로 구독이 끊긴 상태. 허용량은 `무료 + 아직 살아있는 유료 수량`이다. 사용량이 허용량보다 커지면 **초과(over-limit)** 다.

공통으로 하지 않는 것

- 워크스페이스·프로젝트·멤버·파일 삭제
- 위키·칸반·채널·데이터를 상품별로 잠그기
- 초과된 기존 자원을 읽기 전용으로 바꾸기 (이번 범위 아님)
- “무료 플랜으로 강등” 같은 티어 언어

공통으로 하는 것

- 라이선스/내 슬롯 화면에 **N개 부족**
- 생성·초대 API는 `402 SLOT_EXHAUSTED` + 해당 상품 장바구니
- 기존 화면은 그대로 열림

### 워크스페이스 슬롯 (계정 풀)

이 상품만 **특정 워크스페이스에 귀속되지 않는다.** “내가 소유자로 둘 수 있는 조직 수”다.

결제 실패로 유료 워크스페이스 슬롯이 만료되면

| 상황 | 패널티 |
|------|--------|
| 소유 워크스페이스 ≤ 1 (무료 한도 안) | 없음. 유료분만 사라진 것 |
| 소유 워크스페이스 > 1 | **추가 워크스페이스 생성 불가.** 이미 가진 워크스페이스는 전부 사용 가능 |
| 초과분 | `/settings/plan`에 부족 표시. 슬롯을 다시 사거나, 소유 워크스페이스를 줄여 한도 안으로 돌아오게 함 |

소유자 자리가 사라졌다고 멤버를 강퇴하거나 조직을 숨기지 않는다. 초과 상태로 기존 조직을 계속 쓰는 것은 허용한다. 막는 것은 **새 조직 개설**뿐이다.

### 워크스페이스 멤버 슬롯 (워크스페이스 귀속)

좌석은 **그 워크스페이스의 자리**다. 계정 전역 좌석이 아니다. A에서 만료돼도 B의 멤버 한도는 그대로다. 소유자도 1석을 쓴다.

| 상황 | 패널티 |
|------|--------|
| 멤버 수 ≤ 5 (무료 한도 안) | 없음 |
| 멤버 수 > 허용량 | **신규 초대 불가.** 이미 들어온 멤버는 로그인·작업 가능 |
| 초과분 | 해당 워크스페이스 라이선스 화면에 부족. 그 워크스페이스용 멤버 슬롯을 사거나, 멤버를 줄임 |

만료된 워크스페이스에서 프로젝트를 못 만드는 것과는 별개다. 멤버 슬롯만 죽은 것이면 프로젝트 생성은 프로젝트 슬롯만 보면 된다.

### 프로젝트 슬롯 (워크스페이스 귀속)

프로젝트 1개 = 슬롯 1. 위키·칸반·채널·데이터는 프로젝트 안에 포함이고, 프로젝트 슬롯이 없다고 도구만 따로 잠그지 않는다.

| 상황 | 패널티 |
|------|--------|
| 프로젝트 수 ≤ 3 (무료 한도 안) | 없음 |
| 프로젝트 수 > 허용량 | **신규 프로젝트 생성 불가.** 이미 있는 프로젝트는 전부 사용 가능 |
| 초과분 | 라이선스 화면에서 커버되지 않은 프로젝트를 “슬롯 초과”로 표시. 그 워크스페이스용 프로젝트 슬롯 구매 CTA |

프로젝트 슬롯이 만료돼도 기존 프로젝트의 페이지·보드·채팅·데이터는 유지한다.

## 3. 결제일 — 워크스페이스·구매 건을 맞추지 않는다

사용자가 3월 1일에 조직 하나, 3월 15일에 다른 조직을 열면 **결제일을 한날로 합치지 않는다.** 15일짜리를 1일 주기로 끌어오면 남은 날짜가 사라지거나, 반대로 한 달을 통째로 다시 물린다.

### 과금 단위

| 상품 | 귀속 | 결제일 기준 |
|------|------|-------------|
| 워크스페이스 슬롯 | 계정 (워크스페이스 ID 없음) | **구매 건(구독)마다** 독립 |
| 멤버 슬롯 | `workspace_id` | **그 워크스페이스의 구매 건마다** 독립 |
| 프로젝트 슬롯 | `workspace_id` | **그 워크스페이스의 구매 건마다** 독립 |

멤버·프로젝트는 워크스페이스가 다르면 구독도 다르다. A를 1일에 사고 B를 15일에 사면 A 멤버/프로젝트는 매월 1일, B는 매월 15일이다.

워크스페이스 슬롯은 조직 ID에 붙이지 않는다. “이 슬롯 = 저 워크스페이스”로 묶으면 조직을 지우거나 소유자를 바꿀 때 구독이 고아 된다. 대신 **산 시점의 구독 건**이 결제일을 가진다. 3월 1일 1개, 3월 15일 1개면 계정에 구독이 두 줄이고 갱신일이 둘이다.

### 같은 날, 한 장바구니에서 수량 N

동시에 산 N개는 한 구독, 결제일 하나. 같은 시각에 샀으므로 일자 손실이 없다.

나중에 같은 상품을 더 사면 **기존 구독 수량을 올리지 않고 새 구독을 연다.** 기존 구독에 units를 더하면 Polar가 주기를 맞추고 일할 정산을 하는데, 그건 이 기획에서 말하는 일괄 계산이다. 추가 자리는 항상 새 구독, 새 `end_date`.

### 금지

- 계정의 모든 슬롯을 하나의 갱신일(anniversary)로 정렬
- 추가 구매 시 이전 구독 잔여 기간을 버리고 새 한 달로 리셋
- 여러 워크스페이스의 멤버/프로젝트 슬롯을 한 인보이스 주기로 합치기
- 워크스페이스 슬롯을 특정 워크스페이스에 귀속시켜 “이 조직의 월 결제일”로 쓰기

### 허용

- 영수증은 `/settings/billing`에 모이되, 라인마다 기간이 달라도 됨
- 해지는 구독 건 단위. 15일짜지만 끊어도 1일짜리는 남음
- 무료 허용량은 구독이 아님

## 4. 사용자가 체감하는 흐름

1. 카드 거절·구독 종료 → 해당 구매 건만 허용량에서 빠짐. 다른 날 산 구독은 유지.
2. 그 워크스페이스(또는 계정 워크스페이스 수)가 한도를 넘으면 화면이 “N개 부족”.
3. 초대/생성 버튼은 막히고 장바구니로 감. 이미 열린 화면은 그대로.
4. 다시 사면 **새 구독이 그날부터** 한 달. 다른 워크스페이스 결제일에 붙지 않음.
5. 초과를 해소하는 다른 길: 프로젝트 삭제, 멤버 제거, 소유 워크스페이스 정리. 삭제는 사용자가 고르는 정리이지 시스템이 하는 패널티가 아님.

---

## 5. 이번에 하지 않는 것

- 초과 워크스페이스/프로젝트 읽기 전용
- 미납 N일 후 자동 잠금·자동 삭제
- `grace_period_months` 유예 (스키마만 있고 정책으로 켜지 않음)
- 스토리지 미납 패널티 (별 미터, 이 문서 범위 밖)
- 한 워크스페이스의 멤버 구독과 프로젝트 구독을 같은 결제일로 강제 정렬

유예나 읽기 전용이 필요해지면 그때 “생성 잠금” 위에 단계를 쌓는다. 지금 확정 패널티는 **생성·초대 잠금 + 부족 표시 + 구독 건별 결제일 독립**까지다.
